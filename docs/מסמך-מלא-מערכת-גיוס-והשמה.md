## 1. סקירה כללית

### מה המערכת עושה
פלטפורמת גיוס והשמה דיגיטלית המחברת בין מועמדות (סטודנטיות להוראה ובוגרות) לבין מוסדות חינוך ברשת אהלי יוסף יצחק — בצורה חכמה, אוטומטית ומהירה.

### הבעיה שנפתרה
לפני המערכת: גיליונות Excel, שיחות טלפון, ניירות — ללא יכולת מעקב, סינון, או שקיפות. המערכת ממרכזת את כל התהליך במקום אחד.

### משתמשים

| סוג | מספר משוער | תפקיד |
|-----|-----------|--------|
| מועמדות | עשרות–מאות | חיפוש עבודה, הגשת מועמדויות |
| מוסדות | ~20–50 | פרסום משרות, ניהול הגשות |
| מנהלי רשת | 2–5 | פיקוח, התאמה, אנליטיקה |

## 3. ארכיטקטורה טכנית

### Stack

| שכבה | טכנולוגיה |
|------|-----------|
| Framework | Next.js 16 (App Router) |
| Language | TypeScript |
| UI | shadcn/ui + Tailwind CSS v4 |
| Database | Supabase (PostgreSQL + RLS) |
| Auth | Supabase Auth (email + Google OAuth) |
| Storage | Supabase Storage (`cvs` bucket) |
| AI | Anthropic Claude Haiku |
| WhatsApp | Green API (bot) + Twilio (notifications) |
| Deploy | Vercel (auto-deploy from GitHub `master`) |
| Font | Heebo (Google Fonts) |
| Direction | RTL (עברית) |

### דיאגרמת ארכיטקטורה

```
[Browser / Mobile]
        │
        ▼
[Vercel Edge — Next.js Middleware]
        │
        ├──▶ [Server Components] ──▶ [Supabase DB (RLS)]
        ├──▶ [API Routes] ──▶ [Supabase DB]
        │                 ──▶ [Anthropic Claude API]
        │                 ──▶ [Green API / Twilio]
        └──▶ [Client Components] (island pattern)
```

### מבנה תיקיות עיקרי


## 4. מסד הנתונים

### טבלאות ראשיות

#### `profiles` — בסיס כל המשתמשים
```sql
id            UUID PRIMARY KEY  (= auth.users.id)
role          TEXT  -- 'מועמדת' | 'מוסד' | 'מנהל רשת' | 'אדמין מערכת' | 'מנהלת מערכת'
full_name     TEXT
phone         TEXT
created_at    TIMESTAMPTZ
```

#### `candidates` — פרופיל מועמדת
שדות עיקריים: `city`, `specialization`, `academic_level`, `availability_status`, `has_cv`, `cv_url`, `bio`, `supervisor_name`, `special_skills`

**סטטוסי זמינות:**
- `מחפשת סטאג'` — סטודנטית המחפשת מקום סטאג'
- `בוגרת מחפשת משרה` — לתפקיד מלא
- `פתוחה להצעות` — לא מחפשת אקטיבית
- `משובצת` — כבר מועסקת
- `לא פעילה` — לא רלוונטית

#### `institutions` — פרופיל מוסד
שדות עיקריים: `institution_name`, `city`, `institution_type`, `is_approved`, `school_type`, `principal_name`

#### `jobs` — משרות פתוחות
שדות עיקריים: `title`, `description`, `city`, `specialization`, `job_type`, `status`, `expires_at`

**סטטוסי משרה:** `פעילה` | `מושהית` | `אוישה` | `בוטלה` | `פג תוקפה`

#### `applications` — הגשות מועמדות
**מחזור חיים:**
```
ממתינה → נצפתה → התקבלה
                └→ נדחתה
         └→ בוטלה
```

#### `interviews` — ראיונות
`candidate_id`, `institution_id`, `job_id`, `scheduled_at`, `status`, `candidate_confirmed`

#### `invitations` — הזמנות ישירות ממוסד למועמדת
`status`: `נשלחה` | `נצפתה` | `התקבלה` | `נדחתה`

#### `notifications` — התראות
`profile_id`, `type`, `title`, `body`, `is_read`, `related_id`

#### `login_otps` — קודי אימות OTP
`user_id`, `phone`, `code`, `expires_at`, `verified`

#### `wa_sessions` — סשנים של בוט WhatsApp
`phone`, `session_type`, `state`, `data` (jsonb), `expires_at`

#### `system_settings` — הגדרות מערכת
`key` → `value` (support_wa_number, contact_email)

## 8. בוט WhatsApp

**ספק:** Green API | **Instance:** 7107618753 | **מספר:** 972559932738

### זרימות הבוט

| פקודה | תגובה |
|-------|--------|
| `שלום` / הודעה ראשונה | זיהוי מועמדת/מוסד, אם לא מזוהה — תהליך רישום |
| `משרות` | רשימת 8 משרות פעילות לבחירה |
| `הגשות` | רשימת הגשות המועמדת + סטטוס |
| `עזרה` | תפריט אפשרויות |
| `כן` / `לא` | אישור/דחיית ראיון או הזמנה |
| `משרה חדשה` | יצירת משרה חדשה (מוסד/מנהל) |

### סשנים

הבוט מנהל סשנים מוגבלי זמן ב-`wa_sessions`:
- `register_candidate` — תהליך רישום מועמדת חדשה
- `browse_jobs` — גלישת משרות
- `apply_job` — הגשת מועמדות
- `create_job` — יצירת משרה (מוסד)
- `confirm_interview` — אישור ראיון
- `confirm_invitation` — אישור הזמנה

### אבטחת Webhook
כל בקשה ל-`/api/webhooks/whatsapp` נבדקת מול `GREENAPI_WEBHOOK_SECRET` (query param `?token=` או header `x-webhook-token`).

## 10. שילובים חיצוניים

### Green API (WhatsApp bot)
- **שימוש:** קבלת הודעות נכנסות, ניהול שיחות, רישום מועמדות
- **משתנים:** `GREEN_API_URL`, `GREEN_API_INSTANCE_ID`, `GREEN_API_TOKEN`

### Twilio (WhatsApp notifications)
- **שימוש:** שליחת עדכונים יוצאים (הגשה, ראיון, סטטוס)
- **משתנים:** `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_WHATSAPP_FROM`

### Inforu (SMS)
- **שימוש:** שליחת SMS לקוד OTP
- **משתנים:** `INFORU_USERNAME`, `INFORU_API_KEY`

### Anthropic Claude (AI)
- **מודל:** claude-haiku-4-5
- **שימוש:** דירוג מועמדים + הסברים בעברית + AI Chat
- **משתנה:** `ANTHROPIC_API_KEY`

### Supabase Storage
- **Bucket:** `cvs` (פרטי)
- **מבנה:** `{userId}/cv.{ext}`

### Resend (Email)
- **שימוש:** התראות מייל (גיבוי)
- **משתנה:** `RESEND_API_KEY`

## 12. אבטחה

### שכבות הגנה

| שכבה | מנגנון |
|------|--------|
| **Auth** | Supabase SSR session על כל routes מוגנים |
| **RLS** | Row Level Security על כל טבלאות ה-DB |
| **API Auth** | `auth.getUser()` בתחילת כל API route |
| **Role Check** | בדיקת role לפני כל פעולה רגישה |
| **Webhook** | `GREENAPI_WEBHOOK_SECRET` token |
| **OTP** | קוד SMS 6 ספרות, תוקף 10 דקות |
| **Cron** | `CRON_SECRET` header על כל cron jobs |
| **Security Headers** | X-Frame-Options, X-Content-Type-Options, XSS-Protection |
| **Input Whitelist** | רשימת שדות מותרים בכל PATCH |

### RLS — עקרונות

- מועמדת רואה רק נתונים שלה
- מוסד רואה רק הגשות למשרותיו
- מנהל רשת / אדמין — גישה לכל
